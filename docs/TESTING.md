# 标准回归测试清单

每次完成一个功能后，先在本地执行自动化检查，再打开 Windows 浏览器做一次可见交互验收。自动化测试会优先拦截“按钮点下去后进入 404/422/错误状态”的问题。

## 必跑命令

```bash
.venv312/bin/python -m compileall -q app tests
.venv312/bin/python -m unittest discover -v
git diff --check
```

`tests/test_navigation_contract.py` 是全站导航契约测试，覆盖：

- 所有模板中的本地链接、表单 `action` 和流式接口是否能匹配已注册路由与 HTTP 方法；
- 所有状态变更表单是否包含 CSRF 防护；
- 删除/取消导入等危险操作是否存在确认步骤；
- Python 处理器中的重定向目标是否仍然存在；
- WeLink 主要按钮在演示数据下是否都返回 303，并回到正确的页面锚点，而不是 404/422。

## 浏览器验收

启动 `uvicorn app.main:app --port 8001` 后，用 Windows Chrome 或 Edge 检查：

1. 登录、退出和匿名访问 `/` 是否分别进入正确页面；
2. 每个主导航入口、返回按钮、分页、筛选和详情链接是否打开预期页面；
3. 每个新增/保存/启用/暂停/删除按钮是否显示处理中状态，并出现成功或可理解的错误提示；
4. 危险操作是否先确认，取消确认后业务数据不变；
5. WeLink 的演示/生产切换、报告生成、消息源批量操作、消息源/接收方编辑和删除、审计台账跳转是否正常；
6. 两个智能问答入口的 Enter/Ctrl+Enter、发送/停止、流式 Markdown、历史对话和重命名是否正常；
7. 日志上传、报告导出/下载、案例发布、工具版本发布和需求评审等关键链路是否无错误跳转；
8. 在 `1011 × 837` 和 `773 × 837` 视口下检查无横向溢出，并查看浏览器控制台没有错误或警告。

验收过程中不要点击真实生产桥接、真实 WeLink 群发送或删除重要业务数据；生产验收应使用已授权的测试群和可回滚数据。

## 新增功能的最低要求

新增一个按钮或跳转时，必须同时补充：

1. 对应的注册路由和成功/失败重定向；
2. 至少一个路由级测试，验证状态码、目标路径和数据变化；
3. 模板导航契约能识别的本地链接/表单；
4. 危险操作的确认、CSRF 和重复提交状态；
5. 本清单中相应的浏览器验收记录，并在 `docs/HANDOFF.md` 记录验证结果。
